大语言模型擅长理解和生成内容，但一次文本生成并不等于完成了一项真实任务。面对“收集资料、分析数据、生成报告并检查结果”这样的需求，系统还需要管理目标、调用外部工具、保存中间状态，并根据执行结果决定下一步。

AI Agent（人工智能智能体）解决的正是这个问题。它以模型为推理核心，把感知、记忆、规划、工具和反馈组织成一个可以持续运行的执行闭环。

## AI Agent 是什么

AI Agent 是一种围绕目标运行的 AI 系统。它能够接收环境信息，拆解任务，选择并调用工具，检查执行结果，再决定继续行动还是结束任务。

可以先用一个简化对比理解它与普通问答应用的区别：

| 类型       | 主要交互方式     | 工具使用   | 任务规划        | 持续执行     |
| -------- | ---------- | ------ | ----------- | -------- |
| 大模型问答    | 输入问题，生成回答  | 不一定支持  | 通常只在单次回答中推理 | 通常没有     |
| Copilot  | 根据人的指令辅助操作 | 按需调用   | 以人主导为主      | 有限       |
| AI Agent | 围绕目标自主推进   | 主动选择工具 | 拆解并调整步骤     | 根据反馈循环执行 |

这里的边界不是绝对的。一个产品属于 Copilot 还是 Agent，取决于它拥有多少决策权、能否维护任务状态，以及是否可以根据环境反馈继续行动，而不只是取决于底层使用了什么模型。

## 从工具到 Agent：能力如何逐步增加

Tool、Chatbot、Copilot 和 Agent 可以看作四种能力层级，而不必理解为严格的技术发展代际。

### Tool：执行固定功能

工具按照预先定义的逻辑完成单一操作，例如计算器、翻译程序或数据抓取脚本。它不理解开放式目标，也不会自行决定下一步。

### Chatbot：理解并生成对话

Chatbot 能够根据上下文回答问题，但早期或简单的对话系统通常只生成文本，无法直接操作外部环境。即使回答中包含一套步骤，真正执行这些步骤的仍然是用户。

### Copilot：在人主导下辅助操作

Copilot 被嵌入编辑器、办公软件或业务系统中，根据人的指令生成代码、整理内容或调用功能。它可以操作工具，但任务节奏和关键决策通常由人控制。

### Agent：围绕目标持续行动

Agent 在获得目标和权限后，可以规划多个步骤，主动调用工具，读取工具结果并调整方案。它不只是给出“应该怎么做”，还会尝试把任务真正推进到完成状态。

自主性越强，风险也越高。因此，实际系统通常还需要权限边界、操作审批、执行超时和审计记录，而不是让 Agent 无限制地行动。

## AI Agent 的六个核心模块

一个 Agent 不一定严格按照六个独立组件实现，但通常都包含下面这些职责。

### 1. 感知：收集任务与环境信息

感知模块负责把外部信息转换成模型能够处理的上下文，常见输入包括：

- 用户给出的目标、限制和验收条件；
- 网页、本地文件、数据库和业务系统中的数据；
- 工具执行结果与错误信息；
- 历史对话和当前任务状态。

感知不只是“接收一句提示词”。一个能够执行真实任务的 Agent，需要持续了解环境发生了什么变化。

### 2. 记忆：保存上下文与任务状态

记忆让 Agent 不必在每一步都从头开始。按照保存时间和用途，可以粗略分为三类：

- 短期记忆：当前对话、最近一次工具结果和临时数据；
- 任务记忆：任务计划、已完成步骤、中间产物和待解决问题；
- 长期记忆：经过筛选后保存的用户偏好、领域资料或可复用经验。

长期记忆并不等于永久保存全部对话。实际设计中还要考虑信息是否值得保留、何时更新、如何检索，以及隐私和数据生命周期。

### 3. 规划与推理：决定下一步行动

规划模块将目标转换为可执行步骤。例如，“撰写一份电子产品市场报告”可以拆成：

1. 明确报告范围和时间区间；
2. 搜集并核验行业数据；
3. 整理主要产品和竞争者；
4. 分析趋势与限制；
5. 撰写并检查报告。

规划不是只在任务开始时生成一次清单。执行过程中出现数据缺失、工具失败或需求冲突时，Agent 还需要重新判断优先级并调整路径。

### 4. 工具调用：把决策转化为操作

模型本身主要负责理解、推理和生成。联网搜索、执行代码、读写文件、查询数据库或操作第三方系统，需要通过外部工具完成。

一次典型的工具调用包含三个阶段：

1. 模型根据目标生成结构化调用参数；
2. Agent 运行时校验权限并执行工具；
3. 工具把结果或错误返回给模型。

工具接口越清晰，Agent 越容易稳定使用。参数含义、返回结构和失败条件如果含糊，模型即使选对工具，也可能产生错误操作。

### 5. 执行与反馈：记录环境变化

工具完成操作后，Agent 需要把结果写回任务状态。例如，搜索工具返回了若干资料，代码执行器生成了一个文件，或者业务接口拒绝了请求。

这些结果既是阶段性产出，也是下一轮决策的输入。只发送指令却不读取反馈，系统就无法确认操作是否成功。

### 6. 校验与调整：判断是否达到目标

校验模块负责回答三个问题：

- 当前结果是否满足用户要求；
- 信息和产物是否完整、准确；
- 任务应该结束、重试，还是重新规划。

“反思”不是某种神秘能力，本质上是系统显式安排模型或规则检查结果。它可能发现资料缺失后重新搜索，也可能在代码测试失败后修改实现。

不过，模型自检不能替代外部验证。计算结果应交给程序复算，代码应运行测试，关键事实应核对可靠来源，高风险操作还需要人工确认。

## 三层视角下的工作流程

如果不关注内部模块的细节，还可以把 Agent 简化为感知层、大脑层和执行层：

一次完整循环大致如下：

1. 感知层收集用户需求、文件、网页和工具反馈；
2. 大脑层读取记忆，判断当前状态和下一步行动；
3. 执行层调用工具并改变外部环境；
4. 执行结果重新进入感知层；
5. 系统检查目标是否完成，未完成则开始下一轮。

这个循环不是越长越好。Agent 应该有明确的停止条件，例如验收标准已经满足、达到最大重试次数、超出时间或费用预算，或者遇到必须由用户决定的问题。

## 一个简单的任务示例

假设用户要求：“读取销售表格，找出下降最明显的产品，并生成一页摘要。”

Agent 可以按以下方式工作：

1. 读取目标，确认要比较的时间范围和指标；
2. 调用表格工具读取数据；
3. 检查缺失值、字段类型和异常数据；
4. 使用计算工具比较各产品的销售变化；
5. 生成摘要文档；
6. 重新读取产物，核对数字与格式；
7. 如果校验通过则返回文件，否则修正后再检查。

这个例子中，大模型负责理解目标和组织步骤，工具负责可靠地读取、计算和写入数据，记忆负责维护中间状态，校验流程负责降低错误率。任何一个环节缺失，都可能让任务停留在“给出建议”，而不是“交付结果”。

## 设计 Agent 时需要注意什么

首先，目标和停止条件必须清楚。“尽可能完善”很难判断何时结束，而“生成包含三个部分、数据截至指定日期的报告”更容易执行和验收。

其次，工具权限应遵循最小化原则。只读分析不应获得删除权限，外发消息、付款和发布内容等操作应保留明确的确认环节。

再次，关键步骤要有可验证的反馈。工具返回“调用成功”不代表最终结果正确，系统还需要检查文件是否生成、数据是否完整，以及产物是否符合约束。

最后，应为失败路径预留边界。重试次数、执行时间、费用预算和人工接管条件，都是 Agent 稳定运行的一部分。

## 总结

AI Agent 不是单独的一种模型，而是一套围绕目标组织模型、记忆、工具和反馈的系统。它与普通问答应用最关键的区别，在于能否读取环境变化并持续决定下一步行动。

理解 Agent 时，可以抓住一个核心闭环：感知信息，维护状态，规划行动，调用工具，读取反馈，再校验目标。真正决定系统可靠性的，也不仅是模型能力，还包括工具接口、权限控制、停止条件和外部验证。
