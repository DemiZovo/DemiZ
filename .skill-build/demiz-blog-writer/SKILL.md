# DemiZ 博客写作

## 明确任务

- 从用户材料中确定主题、读者、目标和已验证事实。
- 信息不足但不影响主体时，作最小合理假设并明确标注；不要虚构版本号、运行结果、性能数据或个人经历。
- 用户只要大纲、标题或润色时，仅交付所请求的内容；用户要求完整博客时，输出完整 Markdown 文件。

## 保持网站语气

- 使用自然、清晰、克制的简体中文，像程序员整理自己的学习与实践记录。
- 直接交代问题和背景，先说明“为什么”，再说明“怎么做”。
- 保留个人判断，但必须区分事实、经验和建议。
- 使用短段落；每节只处理一个核心问题。
- 准确解释术语，避免术语堆砌、空泛铺垫和刻意炫技。
- 禁止夸张标题、营销话术、网络热词、表情符号以及“希望对你有所帮助”等模板化结尾。

## 组织完整文章

根据主题灵活采用以下顺序，不要为了套模板而制造空章节：

1. 简短说明问题背景。
2. 明确目标、环境和约束。
3. 解释方案选择及其原因。
4. 分步骤展示实现过程与关键代码。
5. 记录容易踩坑的地方、验证方式和限制。
6. 总结可迁移到其他项目的经验。

主要章节使用二级标题。仅在确实需要分层时使用三级标题。代码块必须注明语言；命令、路径、字段和代码标识符使用反引号。

## 生成 Astro Markdown

完整博客必须以以下 frontmatter 开头：

```yaml
---
title: 准确、克制的文章标题
description: 一句话概括文章解决的问题
slug: lowercase-kebab-case
published: YYYY-MM-DD
category: 技术分类
tags: [标签1, 标签2, 标签3]
draft: true
featured: false
toc: true
---
```

遵守以下规则：

- `title` 不超过 100 个字符。
- `description` 不超过 240 个字符，优先控制在 80 个汉字内，并包含用户可能搜索的核心词。
- `slug` 只使用英文小写字母、数字和连字符。
- 未指定日期时使用当前日期；不要添加未来日期。
- `category` 选择一个稳定、明确的技术领域。
- `tags` 使用 2–5 个一致且便于检索的标签，保留技术名称的标准大小写。
- 新文章默认 `draft: true`；只有用户明确要求发布时才设为 `false`。
- 只有真正重要或适合首页推荐的文章才将 `featured` 设为 `true`。
- 仅在存在多个有效章节时启用 `toc`。
- 需要封面时添加 `cover: /images/blog/<slug>/cover.webp`，正文图片使用 `/images/blog/<slug>/...`，并提供准确的替代文字。

## 校验输出

交付前确认：

- 标题、摘要、正文解决的是同一个问题。
- 所有代码、命令和配置在上下文中自洽。
- 没有编造未经用户材料或可靠来源支持的事实。
- Markdown 层级连续，代码围栏闭合，frontmatter 字段合法。
- 结尾给出真正值得保留的经验或边界，不重复全文。
- 用户要求写入网站时，将文件保存到 `src/content/blog/<slug>.md`，再运行项目已有的内容检查与构建命令。
